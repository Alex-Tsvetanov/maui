# AndroidX + Google Material dependency closure for the Android app hosts, resolved out of the LOCAL
# NuGet cache (~/.nuget/packages) that MauiReference itself restores against — nothing is downloaded.
#
# WHY: MAUI's Android app is a MauiAppCompatActivity under Maui.MainTheme, whose base parent is
# Theme.MaterialComponents.DayNight (see src/Core/src/Platform/Android/Resources/values/styles.xml).
# That theme is what gives MAUI's EditText/DatePicker/TimePicker/Picker their Material field chrome and
# its ProgressBar/Switch their Material metrics. The app hosts used to link android.jar only, so they
# inherited Theme.DeviceDefault and rendered framework chrome a few px off MAUI's on every field-bearing
# page. Linking these AARs lets src/platform/android/apphost/res/values/styles.xml parent on the REAL
# Theme.MaterialComponents.DayNight and reproduce Maui.MainTheme item-for-item.
#
# FORMAT: <nuget-package-id>/<path-within-the-versioned-package-dir>. ORDER IS DEPENDENCY ORDER — it is
# the aapt2 resource-overlay precedence (later entries win) and must stay lowest-level-first, because
# material and appcompat both define styleable/SearchView and material and constraintlayout both define
# styleable/Carousel; as overlays they merge, as co-equal inputs they are a hard link error.
#
# The androidx multiplatform FACADE artifacts (xamarin.androidx.lifecycle.runtime,
# .lifecycle.viewmodel, .savedstate, ...) are deliberately absent: they ship an empty classes.jar and
# only redirect to the `.android` variant listed here. android_aar_stage.py drops them anyway.
